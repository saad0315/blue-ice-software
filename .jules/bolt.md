## 2024-06-07 - Consolidating parallel `.count()` and `.aggregate()` queries
**Learning:** The `getDriverStats` and `getDriverDetailStats` functions have performance bottlenecks specific to this codebase due to numerous parallel `.count()` and `.aggregate()` queries on the `Order` model with overlapping conditions (e.g. `driverId`, `scheduledDate`). While running in `Promise.all` mitigates time spent, it still puts an unnecessary connection and execution load on the database. Using `db.order.groupBy` and summing up the required parts in memory is more efficient.
**Action:** When finding multiple parallel database queries fetching stats on the same table with overlapping base conditions, combine them into a single `.groupBy` query and compute the final variables in memory. Always ensure `totalOrders` is calculated by summing counts instead of leaving it out or querying again. Also ensure conditional checks on enums are correctly typed (`as any`) for TS compatibility and sums on decimals are parsed properly.
