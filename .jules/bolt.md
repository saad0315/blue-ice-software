## 2024-05-18 - [Optimize driver stat queries with Prisma groupBy]
**Learning:** Consolidating multiple parallel `db.order.count` and `db.order.aggregate` queries using `db.order.groupBy` significantly reduces database round-trips for dashboard aggregations. However, when migrating `where` clauses to in-memory filters, be extremely careful to exactly replicate the original database-level array subsets (e.g., `status: { in: [OrderStatus.SCHEDULED, OrderStatus.IN_PROGRESS] }`) instead of accidentally merging standard "pending" definitions that might alter historical behavior.
**Action:** When migrating complex parallel queries to in-memory grouping derivations, write the new memory array `.filter()` criteria side-by-side with the old `where: { ... }` object literal to ensure exact functional parity before replacing.
